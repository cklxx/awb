# 多 Agent 组织手册（康威定律版）

两轮实验的记录摘要。实验对象：代码霍格沃茨。

本文未附原始运行日志、代码版本、计时边界和验收产物，数据尚未独立核验。下述数值只作观察记录，不用于证明组织形式的性能优势或设定通用拆分阈值。

## 一句话结论

组织是任务的函数。任务越复杂，验收门加契约的价值越高，组织税越值得交。

## 两种组织形态

| | 并行分工型 | 流水线型 |
|---|---|---|
| 适用 | 模块可独立交付 | 阶段强依赖（前阶段输出是后阶段输入） |
| 例子 | 实验 1：三文件并行改 | 实验 2：审计→重构→验证 |
| 主理人裁定次数 | 少 | 极少（实验 2 仅 1 次） |
| 关键风险 | 集成冲突 | 前阶段输出失真 |

## 角色库

- 主理人：拆任务、写契约、跑验收门、做集成。唯一的跨角色桥梁。
- Owner：按契约交付一个模块。只看契约加自己的文件。
- Profiler（流水线）：只输出审计表加 Top1 推荐，不动手改。
- Reworker（流水线）：按审计表重构，不看 Profiler 的原始脚本。
- Verifier：独立复跑全部验收门，给出 PASS/FAIL，不参与建造。
- Integrator：合并多份改动（小任务可由主理人兼）。

## 验收门（映射 awb check）

每个里程碑交付后，主理人亲自检查该阶段验收项：通过记 verified（⊢），
不通过打回并记一次返工。最终再加 Verifier 独立复核。

## 契约（CONTRACT.md）

契约是组织间唯一的接口，包含：目标定义、产出格式、验收标准、口径定义。
实验 2 摘要记载：Reworker 只靠契约里的 AUDIT.md 加 baseline.json，
不看 Profiler 原始脚本，复算 N_draw=250 分毫不差。契约即接口。

## 实验数据

### 实验 1：简单任务（新增路灯变体，三文件）

| 指标 | 单 agent | 康威组织（并行分工） |
|---|---|---|
| 总耗时 | 3 分 42 秒 | 约 7 分钟 |
| 返工 | 1 次 | 1 次 |
| 跨角色消息 | 0 | 10 条 |
| 最终质量 | tsc 0 错，测试 21/21 | tsc 0 错，测试 21/21 |

结论：小任务上组织没赢（耗时翻倍）。但返工位置从个人试错移到集成验收门，
契约缺口沉淀为组织资产。

### 实验 2：复杂任务（3D 管线性能审计加 Top1 重构）

| 指标 | 单 agent | 康威组织（流水线） |
|---|---|---|
| 找到的 Top1 | 删未用 uv：M_geo −17.1% | TILE 24→48：N_draw −22.4% |
| 总耗时 | 13 分钟 | 19 分钟 |
| 返工 | 1 次（bench 方法论） | 0 次 |
| 跨角色消息 | 0 | 6 条 |
| 验收门一次通过 | 是 | 是 |

记录中的流水线方案耗时比单 agent 多约 46%（19 / 13 − 1），返工记录为 0 次。
两组修改的是不同对象，M_geo 与 N_draw 也不是同一指标，不能据此判断哪组性能更好。

## 硬规则

1. 主理人是唯一的跨角色桥梁，role 之间零直接对话。
2. 先写契约再派发；无契约不派发。
3. 每个里程碑必须过验收门；不通过打回，记返工。
4. Verifier 独立于建造者，复跑全部验收门。
5. 瓶颈指标：跨角色消息全部经主理人时，主理人是单点——任务再大需拆分主理人。
6. bench 契约必须规定"中位数 of N 次"，不接受单次测量（T_build 噪声 ±30% 的教训）。
7. 返工分两类记：代码返工（验收不通过）与方法论返工（bench/等价性脚本自证失败）。
8. 验收门内给 role 自主修正空间：小偏离自行修复，不升级成跨角色沟通
   （实验 1 M3 自主修复第二个隐藏冲突，未产生额外消息）。

## 选型流程

1. 判断任务类型：模块并行 or 阶段流水线。
2. 按上表选组织形态，配角色。
3. 写 CONTRACT.md（目标、格式、验收、口径）。
4. 派发→验收门→集成→Verifier 复核。
5. 沉淀：契约缺口、返工原因写入组织资产。

## Agent 核心特点（与人类的区别，设计必须考虑）

1. **验证成本单独估算**：实验摘要记录了较长的验证阶段，但缺少原始计时证据。
   → Verifier 独立成角色；bench 契约规定"中位数 of N 次"。
2. **上下文是硬约束**：role 先读契约、目标文件和适用的项目规则。
   可按需补充依赖、调用方和测试。摘要中的审计耗时分别为 8 分钟和 2.5 分钟，尚不能归因于上下文范围。
3. **并行有启动和资源成本**：每个 subagent 的上下文加载时间需在当前环境测量。
   任务太小不值得拆（实验 1：组织 7 分钟 vs 单干 3.7 分钟）。
4. **无长期记忆**：隐性知识只存在于契约和文档。CONTRACT.md 是唯一的组织资产。
5. **自信的假阳性**：单 agent 的 equiv 空转——112 PASS 全是同一份数据，自己发现不了。
   → Verifier 必须独立复现，不是"再检查一遍"。
6. **主理人是单点瓶颈**：跨角色消息全经主理人。消息限一句话事由，任务再大需拆分主理人。

## 拆分决策

比较单 agent 的预估耗时与拆分后的关键路径耗时加启动、契约和协调成本。
只有预估节省的时间覆盖额外成本，才以提速为由拆分。
流水线的依赖阶段仍需顺序执行，不能把全部阶段都计作并行收益。
需要独立验证时，另列质量收益和额外成本；本文两轮记录不足以给出通用时间阈值。
